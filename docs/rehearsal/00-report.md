# FDE 工作流首轮合成案例演练报告

对应设计：[设计稿 0.5](../fde-skill-design.md)。本轮范围：完善设计并进行合成项目纸面推演。

本报告保留当时设计阶段的结论。当前实现与验证见 [首版验证记录](../validation-v0.1.md)，最终选定的项目许可见仓库 [LICENSE](../../LICENSE)。

## 结论

三个合成案例在纸面上得到不同承接建议：小范围定制可有条件承接；既有产品遇到数据及组织阻碍时先限定诊断或等待前置条件；范围、成本、付款与能力明显不匹配时暂不承接。

本轮将资产及服务责任、最低交付验证和指标口径补入设计。没有发现需要继续扩展首版业务范围的新阶段，可以进入最小版本实现准备。

这是由同一设计者编写并核对的纸面演练，预期结论也是本轮推演的一部分。它不能证明正式 skill 已具备上述行为，也不能替代新手实际使用、独立会话测试、软件开发、客户试用或验收。

## 案例入口

| 案例 | 刻意覆盖的条件 | 演练建议 | 详细材料 |
| --- | --- | --- | --- |
| A：单机排练室预约工具 | 新手、从零定制、离线、无模型需求、范围变化、验收后尾款待收 | 范围和投入条件成立时承接；新需求单独决定 | [完整旅程](01-custom-project.md) |
| B：既有维保产品接入资产台账 | 已有能力可复用、数据异常、缺正确答案、编码冲突、权限不足、跨会话续接 | 先限定诊断或由客户补齐前置条件，全量实施暂缓 | [数据与组织条件](02-existing-product.md) |
| C：多门店补货与库存协同 | 低预算、高工作量、末期回款、组织整改、未来复制销售诱因 | 当前条件下暂不承接；条件实质改变后重评 | [承接评审](03-decline-project.md) |

所有业务、金额、工时、角色、日期和事件均为新构造的合成输入。它们不取自真实客户材料，不是市场费率、真实效果或通用阈值。

## 流程衔接检查

案例 A 按首次沟通、现状与替代方案、演示计划、需求基线、内部成本与报价草案、合作责任、技术及增量计划、验收条件、回款交接、售后与续接的顺序推演。软件开发与检查结果均未真实发生，后段采用明确标识的场景假设讨论规则如何响应。

| 检查点 | A 中的依据或产物 | 结果或限制 |
| --- | --- | --- |
| 先确认真实问题和购买条件 | A-S01—A-S03 | 无耗时基线，因此不承诺节省工时或现金收益 |
| 演示用于收敛规则 | A-S04、A-R02 | 相邻时段规则进入需求；不升级为采购或验收认可 |
| 报价覆盖交付和服务 | 工时、现金及分摊成本、基准与不利情形 | 参数有场景来源，内部测算与对外草案区分 |
| 合作责任和资产安排明确 | 资产、服务、备份及客户配合草案 | 内容仍待当事方确认，不能自称合同已成立 |
| 需求影响技术与验收 | A-R01—A-R05、A-T01—A-T05 | 条件可检查；没有把检查计划写成测试通过 |
| 新需求不自动改变范围 | CH-A01、D-A02、A-R1 | 手机接入暂缓，保留原范围及理由 |
| 验收前检查必要证据 | A-S06 的恢复证据缺口 | 应保留待验证状态，不因演示成功报告可交付 |
| 验收与付款分开 | A-S07 的模拟后段事件 | 演练内尾款仍待收；真实状态没有验收或收款 |
| 交接支持独立使用 | 数据导出、构建和使用说明、备份责任 | 这些是应交付内容，不是已经生成的软件材料 |

案例 B 在全量实施前停下，案例 C 在商机筛选与承接评审后停下，均无需为了走完流程生成无用架构和开发文档。

## 实际执行的计算与样本核对

已运行 [核对脚本](check-fixtures.ps1)，读取 [合成输入](fixtures.json)，生成 [计算结果](checks-result.json)。该脚本只核对费用、收支安排与样本分类；没有执行正式 skill 或客户软件。

| 项目 | 实际算得的结果 | 对设计判断的意义 |
| --- | --- | --- |
| A 基准与不利成本 | 6,000 元／8,400 元；候选收入 9,600 元 | 预计利润分别 3,600 元／1,200 元，不能只看开发工时 |
| A 时间与最大垫资 | 42／58 小时；240／1,080 元 | 与本案 60 小时、1,200 元投入限制比较，不自动授权延期收款下继续工作 |
| B 样本分类 | 12 条中 5 条直接可处理，2 条规范化后可处理，5 条待核实 | 样本覆盖率约 58.33%，不是正确率；不能推断全量比例 |
| B 待核实记录 | 缺编码 1、未知编码 1、多义编码 2、非法日期 1 | 均保留待核实，未自动分配资产 |
| B 诊断成本 | 8 小时成本 1,800 元；12 小时上限成本 2,400 元 | 候选费用 3,000 元，不能无边界投入或保证整改成功 |
| C 基准与不利成本 | 41,280 元／50,080 元；候选收入 20,000 元 | 预计亏损 21,280 元／30,080 元；尚非无限整改的损失上限 |
| C 资源与现金 | 基准 176 小时、最大垫资 8,400 元；可用仅 100 小时、3,000 元 | 盈利、时间与现金分别不满足当前条件 |

收支表的累计现金余额与项目利润是不同概念。例如 C 最终收到款后现金仍为正，却在计入个人时间和分摊成本后亏损。将两者分别记录，避免“账户还有钱”被误判成项目赚钱。

## 本轮对设计的修正

| 推演暴露的歧义 | 已加入设计 0.5 的规则 |
| --- | --- |
| 交付后谁持有源码和账号、谁付持续费用未展开 | 按对象约定权利、账号、费用、维护及退出安排，不预设统一归属 |
| 将售后成本准备当成对客户的服务限额 | 工时准备与服务承诺分别记录；按现有范围和约定区分缺陷与新增需求 |
| 功能演示顺利可能掩盖恢复、异常和独立使用缺口 | 需求关联版本、方法、预期和实际证据，按风险选择最低检查 |
| 匹配覆盖率可能被称作正确率 | 分别记录总量、可处理、待核实和有正确标签的数量；异常样本不推全量 |
| 一次验收可能被写成软件上线、采用和回款全部完成 | 技术验证、试点、验收、部署及回款独立记录 |

修改集中在已有流程的具体判断，没有加入新的通用市场价格、固定文档数量或所有项目必须经过的收费环节。
