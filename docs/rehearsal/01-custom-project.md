# 案例 A：单机排练室预约工具

性质：完全合成的设计演练。人物、业务、数字、事件与决定均为本次构造，与真实客户无关。所有金额和工时只用于检查测算，不能作为市场价格或其他项目默认参数。

## 入口与初次回应

模拟使用者：不熟悉编程，希望为一个小型排练场地做预约工具，询问“客户说想做一个预约系统，我该先做什么？”

AI 的第一步应是确认本轮业务与购买路径，而非立刻生成网站。可先解释：“先弄清楚现在怎样预约、最容易出错的步骤，以及谁能决定购买。你先收集下面这些信息，AI 再协助整理。”

只询问当前会改变方案的事项：

1. 实际操作人员怎样完成预约、取消和查找空闲时间？
2. 谁确认业务规则与费用，有没有预算和必须满足的使用环境？
3. 是否已尝试现成工具，为什么不适用？

## 模拟材料与证据状态

以下来源均是场景输入，不是真实访谈或实测：

| 来源编号 | 注入的场景材料 | 允许得出的结论 |
| --- | --- | --- |
| A-S01 | 前台负责两个排练室，手工登记会出现时间冲突；没有测过每周耗时 | 存在待核实的冲突问题；不能宣称节省了多少工时 |
| A-S02 | 场地负责人决定采购；本轮预算上限为 9,600 元；希望单机离线工作 | 有一个预算与决策人假设，仍需确认范围和报价 |
| A-S03 | 场景假定已比较纸质登记、表格及候选预约产品；客户需要不等长时段、冲突拦截及修改记录，已比较的候选方案未满足本轮组合条件 | 有理由继续研究小型定制；不是现实中的产品调查结果 |
| A-S04 | 前台看过一条预约到取消的示意流程，提出相邻时段应允许预约 | 更新规则，不等于接受软件、报价或正式验收 |
| A-S05 | 需求确认后负责人提出增加手机远程预约；随后在模拟决定 D-A02 中选择本轮不增加 | 形成变更记录，保持原范围；不能免费扩大系统和权限边界 |
| A-S06 | 模拟开发检查记录尚缺恢复检查证据 | 不能进入可交付状态；继续准备不受影响的培训和交接材料 |
| A-S07 | 后续场景假定补齐版本对应的检查材料，前台完成独立试用，负责人确认验收；第一、二笔款已到，尾款未到 | 仅在演练内进入验收完成、尾款待收；现实软件仍未开发 |

## 承接初判

建议：在确认 A-S03 及本轮范围、且成本和投入上限可接受的条件下承接。暂不承诺业务收益。关键技术条件仍需在客户目标机器验证。

可用资源是场景设定：交付者可投入最多 60 小时，项目可垫付现金上限 1,200 元；这些不是通用承接标准。

本轮不需要模型 API、云服务器或跨部门整改。AI 应允许采用普通规则与数据库解决问题。

## 方向演示与需求草案

演示只围绕“新建预约 → 冲突提示 → 查看与取消”一条流程，采用可点击原型或低成本本地 Demo；本次只写出演示方案，没有生成原型或视频。

需求基线：A-R1。示意认可、报价认可、软件验收分别记录。

| 编号 | 本轮要求 | 对应验收条件 |
| --- | --- | --- |
| A-R01 | 选择排练室、日期、开始和结束时间，登记预约代号 | 有效输入可保存、查找；开始时间早于结束时间 |
| A-R02 | 同一房间的有效预约不可重叠 | 同房间重叠拒绝；相邻时段允许；不同房间可同一时段预约 |
| A-R03 | 取消预约并保留操作记录 | 取消后释放时段，仍能查看取消记录 |
| A-R04 | 查看当天排班并导出 CSV | 导出内容与当前有效记录一致，取消状态可辨认 |
| A-R05 | 本机离线保存，支持导出和恢复备份 | 重启数据保留；按说明恢复后关键记录和状态一致 |

排除事项：手机远程预约、在线支付、多人并发、跨场地同步、短信提醒及自动营销。预约代号不要求输入真实姓名或电话。

业务规则：时间区间采用开始时刻包含、结束时刻不包含的约定。例如 10:00—11:00 与 11:00—12:00 可相邻，10:30—11:30 与第一条冲突。取消记录不占用时段。

## 内部成本、价格与现金流草案

计算输入见 [合成数据](fixtures.json)。所有金额采用同一演练口径；真实项目需要重新核对费用、税费和交易条件。本段不构成对外报价。

| 成本项 | 工时或金额 |
| --- | ---: |
| 调研与范围 | 4 小时 |
| 原型与反馈 | 4 小时 |
| 实现 | 16 小时 |
| 测试 | 6 小时 |
| 部署培训 | 4 小时 |
| 缺陷修复准备 | 4 小时 |
| 沟通与管理 | 4 小时 |
| 合计个人时间 | 42 小时 |
| 内部时间成本假设 | 120 元／小时 |
| 第三方及交易现金支出 | 600 元 |
| 已付工具等分摊成本 | 360 元 |

基准预计成本为 6,000 元。候选项目价 9,600 元，预计利润为 3,600 元，按收入计算的项目利润率为 37.5%。这是包含个人时间估值的内部估算，不能把现金余额称作利润。

不利情形：增加 16 小时返工、额外现金支出 480 元，成本变为 8,400 元，预计利润 1,200 元，利润率 12.5%，总时间 58 小时。个人时间估值不等同于当期现金支出；如有雇员或协作方，应重新列现金成本。

付款候选：范围及合作确认后 3,840 元、可运行试用版本完成约定检查后 3,840 元、客户验收后 1,920 元。比例仅为本案假设，不推荐为其他项目默认安排。

按数据文件中的阶段内先后顺序计算，基准最大垫资 240 元；全部回款推迟到末期、并发生不利现金支出的情形下，最大垫资为 1,080 元。仍在本案假定的 1,200 元限额内，但不能因此跳过首款条件继续开发；付款条件变化需重新决定是否推进。

## 资产、服务与客户配合草案

| 事项 | 本案拟定安排；仍需双方确认 |
| --- | --- |
| 软件与源码 | 客户获得本轮交付的应用、项目源码、依赖清单和构建说明；已有通用组件及第三方权利单列；本轮定制成果是否可复用另列约定 |
| 数据 | 客户负责业务规则和录入；数据保存在其指定电脑，可导出；交付者不长期留存备份 |
| 账号与持续费用 | 本轮无云服务和模型调用；备份介质由客户提供；未来引入服务需重新确认账号与费用 |
| 使用与备份 | 前台维护记录，场地负责人指定备份责任人和频率，并提供恢复验证环境 |
| 服务 | 草案为验收后 30 日接收本轮范围内缺陷反馈，下一工作日内响应；修复安排按影响和约定处理，不承诺所有问题当日修复 |
| 新增需求 | 手机接入等单独评估，不计入原价 |
| 退出 | 提供数据导出、源码及构建和使用说明，移交指定人员，撤销交付者临时权限 |

售后 4 小时只是成本准备，不能解释为“超过 4 小时就不修本轮缺陷”。

客户需确认房间及时间规则、提供目标电脑和试用人员、确认试点与验收，并按约定付款；逾期影响排期时记录具体影响。

## 技术与分批交付草案

候选方案：本机运行的轻量应用，规则校验与本地数据库配合，提供日期排班、预约编辑及备份导出。具体框架和安装方式由目标环境、交付者能力及打包验证决定；此处不把某技术栈变成所有项目的默认值。

第一批：预约、时间冲突和取消，检查业务规则。第二批：导出、备份恢复、操作记录与安装使用说明。每批提供可运行版本后再核对反馈，本次没有实际生成或运行软件。

变更 CH-A01：手机远程预约涉及外网接入、账号权限与持续运行费用。将影响范围、成本、工期和验收的内容提交负责人决定。模拟决定 D-A02 为暂不增加，A-R1 继续有效；不能因新增需求被提出就自动改变基线。

## 关键验收用例与上线判断

| 用例 | 预期检查 | 本次真实执行状态 |
| --- | --- | --- |
| A-T01 | 同房间重叠拒绝，相邻时段和不同房间允许 | 未执行软件测试 |
| A-T02 | 时间非法或缺少必要字段时给出可理解提示，不保存错误记录 | 未执行软件测试 |
| A-T03 | 取消后可再次预约，取消历史保留 | 未执行软件测试 |
| A-T04 | 关闭重启、导出和恢复后，记录及状态一致 | 未执行软件测试 |
| A-T05 | 客户电脑离线运行，前台按说明独立完成任务 | 未执行客户试用 |

A-S06 下应阻止把软件标为可交付，并说明缺少 A-T04 的证据；不能只用界面录屏代替。A-S07 只是在后续演练输入中假定这些条件得到满足，用于推演交接及收款流程，不形成真实测试报告。

验收依据 A-R1 及对应版本，不追溯要求本轮包含 CH-A01。模拟验收后维护付款台账：已收 7,680 元，待收 1,920 元。完成验收不自动代表回款结束。

## 续接记录与本案发现

演练内续接摘要：需求基线 A-R1；CH-A01 已暂缓；验收仅为场景假设完成；尾款待收；下一动作是按约定跟进款项及完成交接。真实状态：没有开发软件、没有客户确认、没有收款。

发现的设计缺口：原设计未把具体资产责任及服务范围展开；成本中的售后工时可能被误读为服务限额；恢复检查与验收、回款的状态需要独立记录。设计稿 0.5 已明确这些规则。

不从本案例推广：单机形态、30 日服务期、小时成本、预算、付款比例、源码安排和技术方案都不是通用规则。
