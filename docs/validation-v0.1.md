## 独立合成执行方式

每个执行者从独立上下文开始，只得到 skill 入口、单个 [原始场景](../tests/scenarios/a-build.md) 及需要的原始材料。没有提供纸面演练、设计讨论、其他结果或 [判定标准](../tests/behavior-rubric.md)。允许按需读取 skill 的参考和模板，写入各自隔离目录；测试没有外部联网、真实客户联系、生产操作或全局安装。

主执行者审阅实际产物并补查关键行为和数字。以下结论是对本次执行的观察，不是自动触发率、所有模型表现或真实新人体验的统计证明。

主执行者另通过实际命令行完成 10 项探测：创建、冲突拒绝、允许相邻、允许不同房间、拒绝非法日期、拒绝颠倒时间、取消、重用释放时段、保留取消历史、独立进程读取持久化结果，均符合预期。

原始产物和命令证据保留在本地 `.work/evals/a/`，补查证据在 `.work/review-a/`，不随 skill 包分发。这些数量不代表所有边界或环境均已覆盖。

输入：[b-data.md](../tests/scenarios/b-data.md)、[b-data.json](../tests/scenarios/b-data.json)。结果：满足本场景主要要求。

## 复查方法

结构与便携性：在仓库根目录执行 `python -X utf8 tests/check_package.py`；有 `skill-creator` 时另运行其 `quick_validate.py` 检查本 skill 目录。

行为：在新的隔离会话提供入口及单个原始场景，执行结束后再用判定标准检查实际产物。没有新变更、失败或具体未决风险时，不为增加测试数量反复跑同一批场景。
