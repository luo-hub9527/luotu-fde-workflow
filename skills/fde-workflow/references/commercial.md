# 定价、合作与范围控制

用于内部测算、预算沟通、正式报价、合作约定及需求变化。内部价格底线与客户方案分开维护，对外执行沿用适用授权。

## 选择合适的商业结构

先分清卖什么，再选择计费单位与付款安排：

- 从零定制：清晰的交付范围可按项目或里程碑；未知较多时可先限定验证，或约定按投入计费并设上限。
- 已有产品：授权／订阅、实施适配、数据准备、集成及维护分别说明。区分历史研发投入、本轮增量成本和未来服务成本；历史投入的回收策略不是本单新增现金支出。
- 效果分成：仅在收益可测、可归因、客户能够兑现且双方约定清楚时考虑。纯粹释放工时不直接算现金收益。

不用统一人天价、价值百分比、折扣、首付或维护费比例替代判断。市场比较标明地区、时间、服务范围和来源；公开标价、预算、卖方报价及成交价分别记录。实际需要当前价格或法律、税费依据时查询适用的权威来源，不从案例猜测。

## 内部成本与承受能力

按同一币种、服务期限及金额口径列出沟通调研、方案／原型、开发、数据准备、接口、测试、部署培训、项目协调、预期返工、缺陷修复和持续服务，以及第三方消耗。来源不清保留范围或未知，个人时间也有成本。

区分个人时间估值、真实现金支出和分摊成本。计算时使用可执行计算工具核对单位、总额及公式，注明输入来源；不能把缺失成本填成零。关键输入不足时给有前提的范围或补证动作，不给虚假的精确报价。

同口径下：

- 预计项目利润 = 候选／约定收入 − 本轮交付及约定服务成本。
- 项目利润率 = 预计利润 ÷ 同口径收入；与成本加价率区分。
- 若选择目标利润率 m，成本为 C，且 0 ≤ m < 1，目标收入为 C ÷ (1 − m)。这只是内部目标，不保证客户接受，也不是市场价。
- 按真实先后顺序逐笔列现金支出与预计回款，找累计余额的最低点；最大垫资是补足该负余额的金额。期末现金余额不等于利润。已付工具的分摊、个人机会成本与新增现金不可混用。

至少比较基准与有依据的不利情形，如清洗、接口等待、返工、人工核对、服务量或回款延期。说明哪些未知使“不利情形”仍不是损失上限，并与使用者可投入时间、现金及服务容量比较。不能把未经证实的复购和复制销售算入当前订单收入。

执行中记录实际投入与成本，偏离时提出取舍和影响；已有承诺的价格、付款和服务范围需协商，不能自动改单。

## 从预算沟通到可审阅的客户方案

初期可提供假设明确的预算范围；正式报价基于本轮足够清楚的交付物、排除项、数据和客户配合、验收方法、部署条件及关键验证。详细技术选择可在约定范围内继续收敛。

客户方案只放适合对方的信息：问题与目标、交付与边界、可选方案的取舍、进度与前提、报价及有效条件、付款节点、持续费用、验收、服务、变更和退出安排。未知项标为待协商；不能把使用者认可内部建议写成客户同意。

## 权利、费用与责任

具体约定客户获得的软件、源码／构建材料和依赖清单，哪些是已有产品、通用组件或第三方内容；定制成果及经验能否复用另有依据，不预设归谁。

数据、配置、服务器、域名、模型／外部服务账号分别明确持有人、管理者、费用承担者和交接方式。服务价格是否包含授权、调用额度、维护及超额费用须可识别，避免重复计费。

缺陷依据已约定行为与验收判断，新增需求依据范围变化判断；不能只因为修起来费时就归为新增。售后工时是成本准备，不自动成为客户服务上限。明确服务期限、渠道、响应安排及修复处理方式；响应时限不等于承诺完成修复时限。

客户配合写成具体事项、负责人、时间与完成证据。延迟时说明对范围、费用和排期的影响，不假设客户已经接受新的日期。合同与合作条款保持草案及待决定状态，适用地区或专业问题按实际需要核实或协作。

## 需求与范围变化

先比较请求与有效需求、验收和合作约定，区分澄清、原范围缺陷与新要求。小改动不自动算新增，也不自动承诺无成本。

对重要变化记录：请求及来源、当前边界、状态（建议／待决定／已同意／暂缓／拒绝／有争议）、受影响的费用、工期、权限、验收和服务，谁有权决定及证据。可建议本轮完成、用其他事项交换、延期、另立范围或不做，不捏造未来承诺。

取得相应决定后更新需求基线、报价／计划和检查；保存版本与来源。累计的小变化出现实质影响时一并说明，不能靠每项很小掩盖超支。

选用 [内部测算](../assets/internal-costing.md) 和 [客户方案](../assets/customer-proposal.md)；内部测算不得整份直接发送客户。
