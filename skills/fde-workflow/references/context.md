# 项目上下文、能力与证据

用于项目首次绑定、接手或续接，以及资料、工具能力或权限发生变化时。

## 项目绑定与记录

先用当前会话、已有项目说明和指定目录确认项目。没有歧义则复用，不反复询问；多个客户或目录冲突时先澄清。只做一次访谈整理、方案判断或代码任务时，不要求先建立记录系统。

持续项目在使用者选定的私有工作区维护一个简明状态文件，优先沿用现有格式；需要时选用 [状态模板](../assets/project-state.md)。状态文件与客户产物放在项目目录，不放进 skill 安装目录、公开 skill 仓库或集中客户材料库。当前源码仓库若就是客户软件仓库，可在其现有记录位置维护获准的项目说明；不要因此将另一个客户或私密商务材料提交进去。

读写前确认项目范围及材料允许进入当前 AI 环境；使用者已明确允许本次使用的材料沿用该范围，不重复索取同一授权。可读路径不等于可公开或可转发外部服务。权限不足时用获准摘录或合成输入继续独立准备，不绕过边界。

仅保存必要的事实摘要、来源引用、有效决定、缺口、验证结果和下一步，不默认复制原始客户资料。内部成本、报价底线、私人联系方式和凭据不进入客户方案或公共示例。凭据通过目标工具的秘密管理方式配置，记录位置和用途即可。

## 会话开始与结束

开始时核对当前阶段、有效范围与验收版本、最近决定和成果。只读取当前任务所需的源材料；文件不存在时标明缺口，不虚构“上次已经确认”。接手时检查影响本轮判断的遗留声称，如已通过测试、已经部署、某人已经同意；历史记录不是当前授权和运行状态的保证。

结束时保存可续接摘要：已完成、实际验证、未完成、关键决定的来源和状态、责任人与下一动作。范围变更关联受影响的报价、计划、任务和测试。草案及建议可以记录为待决定，不能保存成已确认事实；已有确认的事项直接引用其来源。

## 能力与指导深度

用当前任务判断使用者能否调研、运行软件、理解错误、维护系统；不安排抽象考试。检查工具是否实际具备文件读写、命令执行、联网、文档或演示制作能力。缺哪项就说明具体影响和可替代动作，不宣称已经生成无法制作的产物。

新手：解释目标与判断依据，给出下一项可执行动作及如何判断完成；AI 能做的文件、编码和检查直接做，需要人与客户沟通时提供可编辑提纲。工作超出关键能力时，明确需哪类协作、交接哪些材料。熟练者沿用其工具链与流程，减少重复讲解。

格式按实际需要选择：默认 Markdown；客户要 Word、表格、PPT、视频或安装包时检查相应能力并验证实际文件。脚本、分镜和文案不等于已完成视频；架构说明不等于可运行软件。

## 轻量记录与上游边界

本 skill 的记录是普通项目文件，没有自动脱敏、加密隔离或访问控制保证，不依赖 FDEOps CLI。

若用户明确接入上游 FDEOps 客户记录，遵守其隐私过滤协议：记录访问须经支持隐私检查的 CLI 及当前客户对应的过滤视图；不能直接读原始 `.fde/`、私密块或映射字典作为替代。接口不可用时说明未读取真实记录，只用获准材料继续。本轻量记录机制不是绕过上游协议的入口。

发布教学材料时重新构造合成输入并标明性质；不把“换名字”当成公开授权。真实业务材料、精确指标、截图、元数据及本机路径都可能暴露客户信息，应留在对应私有项目。
