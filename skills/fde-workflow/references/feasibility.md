# 承接、可行性与前置整改

在较大演示、诊断或开发投入前做初筛；样本、验证结果、正式报价或重大条件变化出现后更新。要回答客户值不值得投入，以及交付者能否完成、合理获利并承受现金与责任边界。

## 从证据作出承接建议

| 方面 | 最小必要依据 | 可能改变结论的条件 |
| --- | --- | --- |
| 业务与购买 | 实际任务、问题后果、替代方案、使用者、决策和预算／采购路径 | 价值不足、无买方路径、结果和验收不可约定 |
| 数据 | 获准样本、完整性、一致性、正确答案与确认人、更新来源 | 事实缺失、清洗量未知、口径冲突无人裁决 |
| 技术与接入 | 目标环境、接口、权限、第三方依赖、关键能力的实际证据 | 不可接入、关键表现未证实、缺少可接受替代方案 |
| 组织与整改 | 需改变哪些规则／流程／系统，谁负责及批准、资源和排期 | 跨部门整改成为前置条件，却没有负责人、授权和预算 |
| 交付能力 | 人员、技能、可用时间、部署和服务资源 | 关键能力或协作缺失、排期及持续服务不可承受 |
| 财务与回款 | 同口径收入、完整交付和服务成本、付款节点与资金限制 | 基准或不利情形亏损、垫资超限、责任无边界 |

重要阻碍单列，不用平均总分抵消。没有证据不等于已经失败，也不能当作已经可行。先说明已知、未知、建议及会改变建议的条件。

## 数据问题怎样处理

- 格式、重复和有依据的唯一映射：用获准且适合目的的样本估计清洗工作，纳入范围、成本和验收。
- 原始事实或正确答案缺失：由客户补证或确认；模型不能编造缺失事实。
- 跨部门定义、编码或主数据冲突：由有权业务负责人裁决，保留原值与决定依据。
- 持续产生脏数据：确定输入规范、责任人、维护与人工复核投入，不能以一次清洗代替长期治理。

样本须说明来源、选择方式、覆盖范围与局限；正常、异常和高影响情况按风险纳入。展示总数、可处理、待复核以及有可靠标签可核对的数量。覆盖率不等于正确率；故意挑选的异常样本不推断全量比例。缺项不得静默丢弃以抬高成功率。

企业整改写成具体前置事项：改什么、为何影响本轮、谁负责与批准、投入和截止条件、完成证据。寻找不依赖全企业整改的小范围任务；可由客户先完成、另立委托或协作，不默默包进软件报价。

## 诊断与 PoC 只解决关键未知

先找出最可能改变承接或方案选择的假设，再选便宜、可获得证据的检查。已有产品优先检查适配，不重新验证所有已证明的能力。

验证前记录：问题、允许的输入与环境、方法、投入上限、通过与否定／停止条件、何时复核及谁确认结果。缺少权威业务答案时先解决答案来源；缺少权限时不绕过边界做现场测试。

验证时真实运行最小片段，并检查关键失败路径；涉及使用体验时让实际操作者尝试。仅有合成结果可说明机制，不证明真实质量与采用。人工辅助、模拟接口、样本和未验证内容明确展示。

结论可以是支持、否定、调整或仍不确定。达到投入上限或依赖长期未解决时，交付已有发现及缺口，重新决定后续；不无依据延期、反复重试或保证实施一定成功。收费诊断的验收是约定诊断成果，不是保证给出“可实施”。

## 财务与最终建议

用 [商业与范围](commercial.md) 核对完整成本、基准与有依据的不利情形，并分别看预计利润、累计垫资、可用工时和维护容量。未来销售、续费和未经验证的客户收益保留为假设。

建议选择适合当前证据的一条路径：承接、限定诊断／验证、客户先补前置条件、缩范围、寻找协作后重评、当前暂不承接。说明理由、剩余风险、下一行动及重评条件。用户希望战略投入时单独记录投资目的、权利、损失上限和停止条件，不能默认用预计未来收入覆盖本单亏损。

使用 [调研与承接评审模板](../assets/discovery-assessment.md) 的相关部分即可，不为每个环节创建独立文档。
